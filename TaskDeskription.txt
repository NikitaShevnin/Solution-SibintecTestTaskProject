Необходимо продумать и описать функционал для подсистемы контроля и учёта рабочего времени 
сотрудников — **TimeSheet 0.1**.

На текущий момент решение представляет собой плоскую таблицу Excel, расположенную на сетевом диске, 
в которую каждый сотрудник (или его руководитель) вносит данные — сколько часов в какой день отработал.
Необходимо продумать состав сущностей и их атрибутивный состав (например: сотрудники, подразделения, 
руководители и т. п.).

Продумать сервисный слой для обработки этих сущностей (набор сервисов для обработки данных сущностей, 
список REST/SOAP‑сервисов).

Дополнительно можно описать заголовки этих сервисов (например, вызываем сервис `/api/employees/add`, 
на вход идёт то‑то, на выходе получаем то‑то).

Дополнительно можно кратко описать логику, которая будет выполняться в этих сервисах (например, в 
виде комментариев `// это делается для того‑то, это — для того‑то`).
Дополнительно можно продумать и описать модуль отчётности.

Дополнительно можно выполнить небольшую реализацию данного модуля (например, в виде запускаемого 
`.jar`‑файла со списком атрибутов на вход — название сервиса, список атрибутов).

В качестве БД можно использовать H2 либо CSV‑файл на вход с парсингом, либо зашить тестовые массивы 
с данными — не принципиально.

В выборе исходных данных не ограничиваю: тут полёт фантазии — хоть покемонов вместо сотрудников, 
хоть футболистов.

Если будет реализация, хотелось бы увидеть её в виде небольшого проекта с возможностью собрать 
и кратким FAQ, как запустить.
